# 更新日志

## 2026-08-19：LX 自定义音源导入与备用解析
### 自定义音源管理

- 新增“**音乐来源 → 管理音源**”二级管理界面。
- 支持从本地导入 UTF-8 编码的 `.js` 音源脚本。
- 支持从 HTTP / HTTPS 链接下载并导入音源脚本。
- 自动读取并展示 LX 风格脚本 metadata：
  - `@name`
  - `@description`
  - `@version`
  - `@author`
  - `@homepage`
- 支持查看音源来源、优先级、支持的平台标识、初始化状态和失败原因。
- 支持启用、禁用、删除及调整备用解析优先级。
- 导入内容会持久化保存；游戏重启后自动恢复已导入音源及启用状态。

### 导入与运行保护

- 本地与网络脚本均限制最大体积为 **9 MB**。
- 网络导入仅接受 `http://` 与 `https://` 地址，限制重定向次数、下载超时和响应大小。
- 校验 LX metadata 注释头，拒绝空脚本、缺少头部信息的脚本及重复脚本。
- 每个音源均在独立后台 Runtime 中初始化，不会占用 Minecraft 渲染线程。
- 脚本初始化、单次 URL 解析与脚本 HTTP 请求均有超时保护。
- 脚本发生异常、返回非法 URL 或连续失败时，不会阻塞切歌或影响下一首播放。

### LX JavaScript 兼容层

- 新增 Rhino 运行时，并按 Java **8u502** 兼容目标接入。
- 提供 LX 自定义音源常用桥接对象：

```js
window.lx
globalThis.lx
```

- 当前已实现的核心接口：

```js
EVENT_NAMES
on()
send()
request()
currentScriptInfo
```

- 支持 LX 初始化事件 `inited` 和宿主请求事件 `request`。
- 当前首批实现的动作是：

```text
musicUrl
```

- 自定义音源返回的内容必须是有效的 HTTP / HTTPS 音频 URL；返回结果会继续进入 MuoniumPlayer 原有下载、文件头检测、容器识别、解码与播放兜底链。

### 播放器接入范围

- 来源页面明确分为 **官方音乐源**（网易云音乐、QQ 音乐）与 **自定义源** 两部分。
- 网易云与 QQ 的主页、搜索、歌单、排行榜、账号与歌词功能完全保留，且不会被自定义脚本替换。
- 自定义音源定位为“**用户选用的备用 URL 解析器**”：仅在当前官方来源自身解析失败后尝试一次。
- 不执行跨平台搜索、自动匹配、自动聚合或自动切换。

| 当前官方来源 | 选用的 LX 音源需声明 | 行为 |
| --- | --- | --- |
| 网易云音乐 | `wy` | 原网易云解析失败后，才调用用户选用的脚本 |
| QQ 音乐 | `tx` | 原 QQ 解析失败后，才调用用户选用的脚本 |
| `kw` / `kg` / `mg` 等 | 不会自动转换 | 不进行跨平台搜索或匹配 |

- 自定义音源失败后会继续保留现有播放失败处理与下一首兜底逻辑。
### 自定义源平台手动选择

- 每个已导入音源会显示脚本实际声明的 `WY`、`TX`、`KW`、`KG`、`MG` 等平台按钮。
- 用户点击平台按钮后，播放器会持久化保存“**音源 + 平台**”这一明确选择；不会按优先级或按平台顺序自动尝试。
- 当原歌曲来源与用户选择的平台不同，播放回退仅为这个平台进行一次受限歌曲匹配（歌名、歌手、时长），成功后才把目标平台字段交给该 LX 脚本解析。
- 例如用户手动选用 `KG`：仅尝试匹配酷狗并调用该脚本的 `musicUrl`；不会继续尝试 `KW`、`MG`、`WY` 或 `TX`。
- 原网易云、QQ 音乐的内容浏览功能与当前官方来源选择保持不变。

### 灵动岛与日志反馈

新增以下状态反馈：

```text
自定义音源已导入
自定义音源已就绪
自定义音源解析中
自定义音源解析成功
自定义音源不可用
```

- 解析过程中会显示当前尝试的音源名称。
- 成功时显示解析音源及音频格式。
- 失败时显示简要原因，同时不会影响播放器继续使用既有解析链。
- 控制台日志使用 `[LX Source]` 前缀记录初始化、解析、超时、非法结果及回退信息，便于排查。

### 配置与文件位置


- JSON 文件保存音源索引、metadata、启用状态和排序信息。
- 脚本正文以独立 `.js` 文件保存，便于备份、更新和手动排查。

## 网易云听歌记录同步与灵动岛反馈

### 听歌记录与历史同步

- 新增网易云音乐听歌记录同步功能。
- 接入网易云桌面客户端日志上报方案。
- 使用 NCBL 日志封包、Zstandard 压缩、ChaCha20 加密及 RSA 密钥封装。
- 播放记录通过网易云客户端日志上传接口提交。
- 歌曲成功开始播放后，立即上报最近播放记录（`_plv`）。
- 切歌、停止播放或自然播放结束时，根据本地累计的真实播放时间上报听歌时长（`_pld`）。
- 每首歌曲最多发送一次最近播放记录和一次最终听歌时长记录，避免周期性累计值被服务端重复计算。
- 暂停期间不累计播放时长；拖动进度不会直接增加上报时长。
- 暂时不设置最低播放时长阈值；实际播放达到完整秒数后，结束会话即可上报。
- 未登录网易云账号、关闭同步开关或播放非网易云歌曲时，不会发送同步请求。
- 网络或服务端上报失败不会影响播放器继续播放。

### 灵动岛上报反馈

新增听歌上报结果反馈，分别覆盖最近播放和听歌时长两类事件：

- 最近播放上报成功。
- 最近播放上报失败。
- 听歌时长上报成功。
- 听歌时长上报失败。

反馈包含请求耗时、实际听歌时长和失败原因。例如：

```text
最近播放上报成功 180ms
听歌时长上报成功 时长37秒 220ms
最近播放上报失败 180ms · 服务端未确认 successfiles
听歌时长上报失败 时长37秒 220ms · HTTP 500
```

### 灵动岛通知队列

- 新增灵动岛消息排队显示机制。
- 多条通知同时到达时不再覆盖当前消息，后续消息按到达顺序进入队列。
- 仅有一条通知时，仍按照 HUD 中的“完成停留”时长显示。
- 当存在多条通知时，当前及后续排队消息按“排队间隔”时长依次显示。
- 所有排队消息显示完毕后，灵动岛自动隐藏。

### HUD 配置

新增灵动岛配置项：

```text
排队间隔
```

- 默认值：`1.0 秒`
- 可配置范围：`0.5 秒 - 6.0 秒`
- 配置字段：`dynamicIslandQueueIntervalSeconds`

示例：

```text
完成停留 = 3 秒
排队间隔 = 1 秒
```

- 只有一条反馈时显示约 3 秒。
- 存在多条反馈时，每条排队消息显示约 1 秒。
