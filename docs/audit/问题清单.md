## C · 超时/中断级联缺陷（原项目真实缺陷，已修复）

### C-1 · `CloudMusicApi.playlistTrackAll` 未判空 → NPE  ✅ 已修复

- **现象**：`java.lang.NullPointerException` at `CloudMusicApi.playlistTrackAll(CloudMusicApi.java:204)`。
- **日志位置**：fml-client-latest.log:626–634。
- **根因**：
  1. `playlistTrackAll` 先请求 `/api/v6/playlist/detail`（B-3 超时）；
  2. `RequestUtil.createRequest` 捕获超时后返回 **502 body `{code:502, msg:"Read timed out"}`**（RequestUtil.java:508–520，不抛异常也不返回 null）；
  3. `v6Obj.getAsJsonObject("playlist")` 拿到 `null`（响应里无 `playlist` 字段）；
  4. `playlist.getAsJsonArray("trackIds")`（CloudMusicApi.java:204）对 `null` 解引用 → NPE。
- **影响**：NPE 被 `PlayList.queryMusics` 的 `try/catch`（PlayList.java:100–104）捕获，`musicsQueried=false` 复位，歌单显示为空，可下次重试。**不崩溃，但歌单无法加载**。
- **是否移植回归**：否 —— 原项目同样存在该判空缺口，仅在网络失败时暴露。
- **建议**：`playlistTrackAll` 在 `getAsJsonObject("playlist")` 后判空（或检查 `code==200`），失败时抛可识别的异常/返回空，由上层统一兜底。属「明确失效接口的必要修复」（CLAUDE.md §4 允许）。
- **处置（2026-08-14，已修复）**：`CloudMusicApi.playlistTrackAll`（~line 203）在 `getAsJsonObject("playlist")` 后判空，超时返回 502 时抛 `IllegalStateException`，由 `PlayList.queryMusics` 的 catch 复位 `musicsQueried=false` 重试。编译通过。

### C-2 · 歌曲下载被中断 → 文件被删 → `AudioPlayer.setAudio` 抛 NoSuchFileException  ✅ 已修复

- **现象**：`java.nio.channels.ClosedByInterruptException` at `CloudMusic.writeTo(CloudMusic.java:811)`，随后 `java.nio.file.NoSuchFileException: ...\MusicCache\409926_Standard.flac` at `handlePlayerInitializationError(CloudMusic.java:447)`。
- **日志位置**：fml-client-latest.log:642–672（18:34:37，`Play Thread`）。
- **根因**（完整链）：
  1. 播放 flac 歌曲 409926 → `getCachedOrTempFile` 发现无缓存 → `downloadMusic(playUrl, music)`；
  2. `Play Thread` 在下载中被**中断**（切歌/停止触发），`writeTo` 抛 `ClosedByInterruptException`；
  3. `downloadMusic` 的 `catch(Throwable)`（CloudMusic.java:797–803）**吞掉异常并 `music.delete()` 删除半成品文件**；
  4. `downloadMusic` 正常返回 → `getCachedOrTempFile` **不校验文件是否真存在**，返回该已被删除的路径；
  5. `AudioPlayer.setAudio(path)` 打开文件失败 → `NoSuchFileException` → 被 `handlePlayerInitializationError` 打印。
- **影响**：被中断的这次播放失败（用户看到「无法播放」或无反应），但异常被捕获，**不崩溃**。切歌过快时较易触发。
- **是否移植回归**：否 —— 原项目同样吞掉中断异常并删文件、不校验下载结果。
- **建议**：`getCachedOrTempFile` 在 `downloadMusic` 后校验 `music.exists()`；或 `downloadMusic` 中断时不静默删除、向上抛信号让上层走「缓存未命中」分支。属下载中断处理的健壮性缺口。
- **处置（2026-08-14，已修复）**：`CloudMusic.getCachedOrTempFile` 下载后校验 `music.exists()`（不存在抛 `IllegalStateException`）；`initializeAndPlaySong` 将 `getMusicFile` 移入 try/catch，由 `handlePlayerInitializationError` 兜底。编译通过。

### D-1 · 中文输入失效（暂缓）

- **现象**：搜索框只能输入英文，中文（IME 组合字符）无法输入。
- **根因（已审计，非过滤问题）**：`ChatAllowedCharacters.isAllowedCharacter` 允许 `char>=32`，中文可通过。真正原因是原项目中文输入依赖 Opai 客户端提供的 `ingameime.*` JNI 绑定 + `IngameIME.dll`，二者均未随移植引入：
  1. `ingameime.*` Java JNI 绑定（`ingameime.IngameIMEJNI` / `InputContext` / `CommitCallback` 等）——原项目源码中**亦不存在**，由 Opai 客户端 classpath 提供；
  2. 资源已打包 `IngameIME.dll`，但全项目**无 `System.load`/`Native.load` 引用**，DLL 从未加载。
- **本质**：LWJGL2 `Keyboard.getEventCharacter()` 不产生 IME 组合字符，需补一层原生 IME 桥（重构 `ingameime.*` JNI 绑定复用 DLL，或 JNA 自实现 Windows IMM32）。
- **处置**：**暂缓**（2026-08-14 用户确认）。作为已知限制记录；中文搜索暂用 Ctrl+V 粘贴顶替。

### D-3 · 频谱可视化删除

- **处置（2026-08-14，已完成）**：删除 `MusicSpectrumWidget` / `SpectrumVisualizer` / `FFT` / `JSynFFT` / `FFTFactory` / `Transform` 共 6 文件；移除 `AudioPlayer` 的 FFT 回调 / `bandValues` / `visualizer`；`TritiumMusicExtension` 注销 `musicSpectrum`；`MusicLyricsPanel` 移除低频能量背景脉冲。附带消除 headless 冒烟测试的静态回调 `NoClassDefFoundError` 隐患。编译通过。

### D-4 · 中文字体与半角字号不一致（半角偏大）✅ 已修复

- **现象**：歌词页与播放器主页面，数字/字母等半角字符的宽高约为中文的 2 倍，中文显得过小。
- **根因**：Oracle JDK 1.8.0_461（干净客户端实际运行 JVM）对 **CFF/PostScript-outline 字体（`.otf`）存在 2x 缩放 bug**——`deriveFont(size)` 报告的 `getSize2D()` 正确，但实际 `ascent/descent/advance` 都被放大 2 倍。主字体 SF Pro 是 CFF（`sfregular.otf`/`sfbold.otf`），半角字符被放大 2 倍；回退字体 PingFang 是 TrueType（`pf_normal.ttf`/`pf_middleblack.ttf`），不受影响。故出现「半角 2x 中文」。在 OpenJDK/Temurin 8u432 上 CFF 渲染正确，故此前静态分析无法复现。
- **验证数据（12pt 派生，实测 ink/度量）**：

  | JVM | sfregular '0'（半角） | pf_normal '中'（中文） |
  |---|---|---|
  | Temurin 8u432 | ascent+descent=15, advance=8 | ascent+descent=18, advance=13 |
  | Oracle 8u461（修复前） | **ascent+descent=30, advance=15** | ascent+descent=18, advance=12 |
  | Oracle 8u461（修复后） | ascent+descent=15, advance=8 | ascent+descent=18, advance=12 |

- **处置（2026-08-14，已修复）**：`CFontRenderer` 新增 `cffScaleFactor(Font)`——以 100pt 参考字体测量 `ascent+descent`，若 `ratio>2.0`（CFF 被 2x 放大）则返回 0.5，否则 1.0；`init` 与 fallback 构造循环中的 `deriveFont(sizePx*2)` 改为 `deriveFont(sizePx*2*cffScaleFactor(font))`。对 TrueType 与正确 JDK 上 `ratio≈1.2~1.5`，因子为 1.0（无副作用），实现 JVM 自适应。不改变正确 JDK 上的外部行为。
- **是否移植回归**：否——原项目同样用 `.otf` CFF 字体，在 Oracle JDK 上亦会放大；属运行 JVM 差异导致的兼容性问题。
- **编译验证**：`./gradlew compileJava --offline` 通过（仅 deprecation/unchecked 提示，无错误）。
