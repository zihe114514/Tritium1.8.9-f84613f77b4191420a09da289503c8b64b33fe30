# S6-2 · 圆角/裁剪/模糊/Bloom 静态核对（渲染高保真）

## 0. 范围与方法

在无运行时的情况下，对照原项目核对渲染链路的**静态正确性**：shader uniform 接线、GL 调用映射、
GLSL 版本、framebuffer/stencil 附着、圆角/裁剪/模糊/Bloom 的调用链。运行时视觉一致性另需真机复测。

## 1. 已核对并通过（忠实移植）

### 1.1 Shader 基础设施
- `ShaderProgram`：`drawQuad`/`drawQuadFlipped` 用 `GL_TRIANGLE_STRIP` + `glTexCoord2d`，喂给
  `vertex.vsh` 的 `gl_MultiTexCoord0` → `gl_TexCoord[0]`。`start()`=`glUseProgram`，`stop()`=`glUseProgram(0)`。
- `ShaderCompiler.compile`：`glCreateShader/glShaderSource/glCompileShader/glCreateProgram/glAttachShader/glLinkProgram`，
  编译失败会抛 RuntimeException。资源经 `Location.of("/tritium/shaders/"+name)` 读取。
- `Uniform1f/1i/2f/4f` → `glUniform1f/1i/2f/4f`；`UniformFB` → `GL20.glUniform1(loc, FloatBuffer)`（= glUniform1fv）。均带“值未变则跳过”缓存。

### 1.2 GLStateManager shim
`GLStateManagerImpl` 是 GL11/GL13/GL14 的 1:1 透传。shader/渲染层用到的 `enableBlend`/`disableBlend`/
`tryBlendFuncSeparate(→glBlendFuncSeparate)`/`disableAlpha`/`enableAlpha`/`alphaFunc`/`setActiveTexture(→glActiveTexture)`/
`bindTexture`/`colorMask`/`depthMask`/`enableDepth`/`matrixMode`/`loadIdentity`/`ortho`/`translate`/`viewport`/
`enableTexture2D`/`disableTexture2D`/`disableLighting`/`enableColorMaterial`/`callList`/`clearColor`/`clearDepth`/`clear`
全部存在且语义正确。

### 1.3 shader uniform 名称接线（Java 类 ↔ .frag/.glsl 完全一致）
| Java 类 | shader 文件 | uniform（Java 设置 ↔ GLSL 声明） |
|---|---|---|
| RQShader | rq.frag | u_size / u_radius / u_color |
| RQTShader | rqt.frag | textureIn / u_size / u_offset / u_scale / u_radius / u_alpha |
| RQGShader | rqg.frag | rectSize / radius / color1..4 / alp |
| ROQShader | roq.glsl | u_size / u_radius / u_border_size / u_color |
| ROGQShader | rogq.frag | u_size / u_radius / u_border_size / u_color_1..4 |
| GaussianBlurShader | blur.frag | u_radius(int) / u_kernel / u_diffuse_sampler / u_other_sampler / u_texel_size / u_direction |
| BloomShader | bloom.frag | u_radius(float) / u_kernel / u_diffuse_sampler / u_other_sampler / u_texel_size / u_direction |
| StencilShader | stencil.frag | mixTexture(=16) / stencilTexture(=0) |

### 1.4 圆角（SDF 抗锯齿）
RQ/RQT/RQG/ROQ/ROGQ 全部基于 signed-distance-field + smoothstep 抗锯齿，GLSL 1.20 合法
（用内建 `gl_TexCoord[0]`，无 1.30+ 语法）。调用点经 `SharedRenderingConstants.roundedRect*` /
`roundedOutline*` 分发，与 `AbstractWidget` 的圆角组件（RoundedRect/Image/ButtonWidget）一致。

### 1.5 裁剪（两条链路）
1. **GL stencil 裁剪**（`StencilClipManager.beginClip/endClip`，栈式嵌套）：
   CroppedPanel、ScrollPanel、ScrollText、ScrollLabelWidget、TextField、CoverflowOverlay、
   MusicLyricsPanel(进度条/音量条)、MusicInfoWidget(下载/进度)、MusicLyricsWidget、NCMScreen(面板/下载进度)。
2. **shader stencil**（`Shaders.STENCIL`，用 FBO 纹理 alpha 做 mask）：
   MusicLyricsPanel 逐字歌词 karaoke 裁剪、ScrollText 淡边。
   两者职责清晰，实现与原项目一致。

### 1.6 模糊 / Bloom
- `GaussianBlurShader`（歌词模糊）：FBO ping-pong 两次 pass（先水平 `compression=.5`，后垂直），
  自定义 Framebuffer attach `GL_DEPTH24_STENCIL8`（含 stencil）。radius=5。
- `BloomShader`（封面高光）：同构，radius=12，`compression=2`。
- `Framebuffer` 用 MC 1.8.9 的 OpenGlHelper/GL30 建 FBO；`updateMcFramebuffer` 捕获 MC 主 framebuffer 用于回合成。

## 2. 需运行时验证 / 潜在隐患（非移植回归，需真机确认）

### ⚠️ 2.1 GL stencil 裁剪依赖主 framebuffer 有 stencil buffer（最高优先验证）
自定义 Framebuffer 显式 attach `GL_DEPTH24_STENCIL8`（有 stencil），但 `CroppedPanel`/`ScrollPanel` 等
在**屏幕主 framebuffer（framebuffer 0）**上做 GL stencil 裁剪。主 framebuffer 是否有 stencil 取决于
MC 1.8.9 的 Display PixelFormat（本 Mod 不创建 Display，沿用 MC）。若无 stencil，这些裁剪会**静默失效**
（内容溢出、不裁剪），无异常、无报错。
**复测点**：滚动歌单/搜索结果/TextField 文本是否在容器边缘正确裁剪（不溢出）。

### ⚠️ 2.2 歌词模糊 texel size 与 framebuffer 分辨率单位不一致
`GaussianBlurShader`：framebuffer 用 `Display.getWidth()`（原生像素），但 `u_texel_size` 用
`RenderSystem.getWidth()`（GUI 缩放坐标，`ScaledResolution`）。GUI scale > 1 时二者不等（如 2× 缩放 →
模糊采样步长放大 2×，模糊更强）。`BloomShader` 则两处都用 `Display`（一致）。
疑为原项目行为（`WindowResolution→ScaledResolution` 是 C 类适配），但需运行时确认。
**复测点**：GUI 缩放 > 1 时，歌词模糊强度是否明显强于 GUI 缩放 = 1 / 与原项目是否一致。

### ⚠️ 2.3 ShaderCompiler 不检查 link 状态
仅检查 compile（compile 失败抛异常）；`glValidateProgram` 在 `glLinkProgram` 之前调用且结果均未检查。
若 shader **link** 失败（非 compile），会静默产生坏 program（渲染黑/无效果）。当前 vertex.vsh 与各
fragment 只用内建 varying（`gl_TexCoord`），理论上 link 应成功，但属潜在静默失败风险。
S6-1 降级后已无 1.30 语法，link 预期通过；真机若见“某区域全黑/无圆角”，可优先怀疑此处。

### 注 2.4 高斯核 off-by-one（原样保留，不修）
kernel 上传 `radius` 个 float（index 0..radius-1），shader 循环 `i<=u_radius` 会访问 `u_kernel[radius]`
（未初始化=0），最外层采样权重为 0，有效模糊半径少 1。blur(5) 与 bloom(12) 均有。属原项目行为，
按 CLAUDE.md「不改外部行为」保留。

### 注 2.5 OpenGlHelper 简化
`isFramebufferEnabled()` 恒 true，直接用 GL30。MC 1.8.9 要求 GL 2.1，GL30 需驱动支持 GL 3.0
（2008 标准，1.8.9 年代硬件普遍具备）。边缘情况，实际风险低。

## 3. 结论

- 静态核对**未发现明确移植回归**：uniform 接线、GL 调用、GLSL 版本均正确。
- 最需真机确认的两项：**#2.1 GL stencil 裁剪是否生效**、**#2.2 GUI scale>1 时歌词模糊强度**。
- 建议复测顺序：滚动列表裁剪 → 逐字歌词 karaoke 裁剪 → 封面 Bloom 高光 → 歌词模糊。
